# AquaHunter 数据来源与商业再利用政策

状态：发布硬门槛  
最后审查：2026-07-21

## 1. 基本原则

AquaHunter 只在生产版本中使用满足以下条件的数据：

1. 数据来自可验证的官方发布者或已签约供应商。
2. 许可证或合同明确允许商业使用。
3. 许可证或合同明确允许 AquaHunter 所需的复制、转换、聚合和衍生分析。
4. 再分发、缓存、展示、导出和 API 返回均在授权范围内。
5. 产品能够履行署名、同许可共享、保留期限、地域、频率和删除要求。
6. 每条观察记录都保留来源、原始时间、发布时间、抓取时间、转换过程和质量标记。

“公开网页”“免费 API”“可以下载”和“公共机构发布”都不自动等于可商业使用或可二次分发。许可证不明确、仅限研究、仅限个人使用、禁止衍生、禁止再分发或需要另行授权的数据，默认不得进入生产环境。

本政策是工程发布控制，不替代律师对许可证、合同、隐私、海事和各司法辖区法规的审查。

## 2. 发布判定

数据源只有同时满足下列条件，才能进入生产：

- `decision = approved`
- `commercialUse = true`
- `derivativeUse = true`
- `licenseId` 是可核验的明确许可证标识或内部合同编号
- `licenseEvidence` 指向发布者的官方许可或正式合同记录
- `datasetIds` 精确到实际使用的数据集、表、产品或图层
- `productionEnabled = true`
- 署名、缓存、再分发和保留义务已在代码与产品界面落实
- 数据适配器没有虚构、演示或静默回退值

`conditional` 表示发布者总体上可能开放，但具体数据集、上游贡献者、产品手册或使用方式尚未完成审查。`blocked` 表示当前不得用于生产。

权威登记表为 [`data-sources.json`](data-sources.json)。发布前必须运行：

```bash
python3 tools/validate_data_sources.py --release
```

如果生产源为空、启用了未批准来源或登记字段不完整，命令必须失败。

## 3. 每条数据必须携带的溯源字段

后端和客户端展示模型至少保留：

| 字段 | 含义 |
|---|---|
| `sourceId` | 对应登记表中的稳定 Source ID |
| `provider` | 官方发布者或合同供应商 |
| `datasetId` | 实际表、产品、图层或合同数据集 ID |
| `sourceUrl` | 可供用户核验的官方页面 |
| `licenseId` | 许可证标识或内部合同编号 |
| `attribution` | 必须展示或导出的署名文本 |
| `observedAt` | 现实世界中的观测/成交/报告时间 |
| `publishedAt` | 发布者公开该记录的时间 |
| `retrievedAt` | AquaHunter 获取该记录的时间 |
| `validUntil` | 数据不再适合视为当前值的时间 |
| `latencyClass` | 实时、延迟、日、周、月或静态 |
| `originalValue` | 原始数值，不覆盖 |
| `originalUnit` | 原始计量单位 |
| `originalCurrency` | 原始币种，若适用 |
| `transformations` | 汇率、单位、聚合、插值和模型处理步骤 |
| `qualityFlags` | 缺失、修订、估算、保密抑制等标记 |

界面不得把国家出口均价标成某个城市的现货价，不得把卸货港当成捕捞位置，也不得把周/月统计显示成实时数据。

## 4. 当前许可白名单

### 可进入生产适配阶段

- **Statistics Norway Statbank 表 03024**：官方说明允许在注明 Statistics Norway 为来源时自由使用已发布统计和分析。它可用于“挪威养殖三文鱼周度出口量与单位价值基准”，不能标成 Oslo 现货价或买卖报价。
- **GEBCO Grid**：官方条款明确允许复制、发布、改编和商业利用，必须署名；明确禁止用于导航或海上安全用途。
- **OpenStreetMap 数据**：ODbL 允许复制、分发和改编，但必须署名，并对衍生数据库履行同许可义务。仅批准 OSM 数据本身，不批准直接依赖社区标准瓦片服务器。
- **MapLibre Native**：作为开源地图渲染引擎使用；它不是底图或海洋数据许可证。底图仍需独立审批。
- **東京都中央卸売市場日報**（2026-07-21 核准）：东京都开放数据目录以 CC BY 4.0 发布，利用规约明示允许商用；仅可作为"东京批发市场水产日报速报值"，必须署名并注明加工，不得标成实时报价。
- **NASA OB.PG 海温与海色产品**（2026-07-21 核准）：NASA-led 任务数据为 CC0;仅限 OceanColor Web 的 MODIS/VIIRS SST 与叶绿素产品，排除 Earthdata 托管的 CSDA 等第三方商业数据。
- **NOAA OISST v2.1 与公开渔获汇总**（2026-07-21 核准）：NODD 以 CC0-1.0 发布；仅限公开非机密汇总，禁止触碰可识别渔民/渔企的机密明细。
- **EMODnet Bathymetry DTM**（2026-07-21 核准）：欧盟所有、CC BY 4.0，明示允许商业再利用；仅批 DTM 成品，内部源级测深数据须逐条复核。
- **Protomaps OSM builds（.pmtiles）**（2026-07-21 核准）：以 ODbL Produced Work 分发,可裁剪区域离线打包进商业 App,义务为 OSM 署名;托管 API 需另行付费与登记。

以上来源仍须完成具体数据集版本、API、缓存、署名和产品用途实现后，才会设置 `productionEnabled = true`。

### 必须逐个数据集审批

- **Copernicus Marine**（2026-07-21 复核）：总许可明确授予"for any purpose"的商业与衍生权利并强制署名 + DOI；但仍须把具体 Product ID、产品手册、上游限制加入登记表后才可启用，不得把"总体开放"替代产品级审查。
- **各国政府、港口和市场数据**：必须逐表、逐接口保存官方许可证据。

### 当前禁止生产使用

- **FAO**（2026-07-21 复核）：数据库虽为 CC BY 4.0,但 FAO 附加条款禁止"用于促销商业企业";产品决定暂不展示 FAO 数据,如需启用须先法务复核。
- **Global Fishing Watch**（2026-07-21 复核）：API 仅限非商业（默认 CC BY-NC 4.0）,商业集成必须与 GFW 签定制许可；CC BY-SA 下载数据集的同许可传染与商业闭源产品冲突。产品决定不展示。
- ImportYeti、Volza（2026-07-21 复核，条款证据已入登记表）和任何 AIS 服务：在取得与 AquaHunter 商业展示、缓存、分析和再分发方式匹配的书面许可或合同前禁止使用。
- 市场网页抓取数据：在取得明确数据许可、官方开放接口或合同前禁止使用。
- `tile.openstreetmap.org` 社区标准瓦片：OSM 数据开放不代表瓦片服务是免费的商业托管服务；生产应用必须使用自托管瓦片或明确允许商业移动应用的供应商。
- 许可证未知、仅限研究、仅限个人、禁止商业、禁止衍生或禁止再分发的数据。

## 5. 地图方案

- 三端统一使用 MapLibre Native 或平台兼容封装作为渲染引擎。
- 全球底图优先使用自托管、版本固定的 OSM 衍生矢量瓦片，并满足 ODbL 署名和衍生数据库义务。
- 如果采购第三方瓦片，合同必须覆盖商业移动应用、缓存、离线策略、并发、地域和 SLA。
- 不把 Google Maps、Apple Maps、OpenStreetMap 社区瓦片或任何“免费示例 URL”视为默认生产底图。
- GEBCO 只用于海洋智能分析和非导航可视化，并持续显示“不用于导航或海上安全决策”。

## 6. 无数据行为

当没有合规数据、请求失败、数据过期或许可被撤回时：

- 显示“当前无已授权数据”及最后成功更新时间；
- 保留可核验的错误和事件记录；
- 不生成虚构价格、买家、港口、船舶、K 线、Fish Probability 或 AI 结论；
- 不用旧演示数据静默回退；
- AI 只能引用当前可用的合规记录，否则明确拒答。

## 7. 变更与复审

- 每次增加数据源、数据产品、用途、导出方式或收费层级，都要重新审查。
- 许可证、产品手册或服务条款变更时，先停用受影响的生产源，再完成复审。
- 许可证据应保存官方 URL、审查日期和必要的不可变存档摘要。
- 生产数据源至少每季度复审一次；合同数据源按续约日期复审。
